## 一、文档目的与范围

本架构设计书定义忆联 MVP 三端产品（C 端 App、B 端机构后台、平台后台管理）的技术架构，覆盖技术选型、系统架构、数据模型、API 设计、AI 集成、安全与合规、部署运维、测试策略与开发里程碑。

目标：在 22 周试点计划内，以最小成本交付可运行、可审计、可扩展的 MVP，并为后续 AI 能力（声音克隆、影像生成等）预留扩展空间。

## 二、设计原则

- 简单优先：MVP 用单体分层架构 + 容器化部署，不提前引入微服务。
- 部署自主：云厂商与机房由用户自行部署决定，架构保持云中立（S3 兼容存储、自选推送、Docker Compose 可移植）。
- 数据合规：部署位置与数据处理遵守境内合规要求；LLM 使用 DeepSeek API，按服务条款执行数据使用约定。
- 三端一致：C 端 App、B 端 Web、后台管理 Web 共享同一套 API 契约。
- 审计完备：用户、机构、后台三侧敏感操作全部留痕。
- 扩展预留：故事问答接 DeepSeek API；声音克隆、影像生成等后续能力以独立服务形态接入。

## 五、系统架构

```
┌─────────────────────────────────────────────────┐
│ 客户端层                                        │
│  C 端 App (Flutter)  B 端 Web  后台管理 Web      │
└───────────────────────┬─────────────────────────┘
                        │ HTTPS + JWT
┌───────────────────────▼─────────────────────────┐
│ 接入层                                          │
│  CDN / WAF / API Gateway（限流、鉴权、审计）    │
└───────────────────────┬─────────────────────────┘
┌───────────────────────▼─────────────────────────┐
│ 应用层（Java/Spring Boot 单体服务，按模块分包） │
│ 用户/档案/家族/问答/纪念册/推送/机构/结算/后台   │
└──────┬──────────────────┬──────────────┬────────┘
       │                  │              │
┌──────▼──────┐   ┌───────▼──────┐   ┌───▼──────────┐
│ PostgreSQL  │   │ Redis        │   │ 对象存储     │
│ 业务+审计   │   │ 缓存/队列    │   │ (S3兼容)+CDN │
└─────────────┘   └──────────────┘   └──────────────┘
       ┌───────────────────────────────────┐
       │ AI 集成（DeepSeek API）          │
       │  安全过滤 → 记忆检索 → LLM → 审核 │
       └───────────────────────────────────┘
```

### 5.1 分层说明

- 客户端层：三端通过统一 API 访问服务端；C 端 App 内置图片/音频上传、推送、支付（试点期以机构渠道结算为主，暂不做应用内支付）。
- 接入层：CDN 加速静态资源；WAF 防护；API Gateway 做统一鉴权、限流与审计。
- 应用层：Spring Boot 单体按领域分包（user、lovedone、family、qa、album、event、partner、admin），模块间通过内部接口解耦，为后续拆分微服务留边界。
- 数据层：PostgreSQL 存业务与审计数据；Redis 存会话、限流、队列；对象存储（S3 兼容）存照片/录音/视频/纪念册，CDN 分发。
- AI 集成：故事问答通过 Spring WebClient 调用 DeepSeek API（OpenAI 兼容端点），SSE 流式输出经 SseEmitter 转发，输入输出均经过安全过滤，所有交互记录入库。

### 6.2 数据规则

- 故人数据必须绑定"创建者"与授权成员；机构只能关联订单与引导记录，不可关联隐私素材内容。
- 永久删除必须级联：conversations、media_files（对象存储对象）、albums、相关缓存与备份。
- 授权记录与审计日志不可被普通用户或机构删除。

## 七、API 设计

- 风格：REST + JSON，统一前缀 /api/v1。
- 契约：OpenAPI 3.0 文档随代码维护（springdoc-openapi），前后端按契约联调。
- 统一响应：{ code, message, data }；错误码分段：1xxx 认证、2xxx 参数、3xxx 业务、4xxx 权限、5xxx 系统。
- 鉴权：JWT（Access + Refresh），Spring Security 实现；后台管理额外 TOTP 双因素。
- 限流：普通接口每用户 60 req/min；故事问答 10 req/min；机构结算接口按机构限流。
- 幂等：订单、删除请求等写操作带幂等键。
- 主要接口见 PRD 第十二章，开发前输出完整 OpenAPI 文档。

## 八、AI 集成设计（故事问答）

### 8.1 调用链路

用户提问 → 输入安全过滤（敏感词/自伤/诈骗识别）→ 记忆检索（结构化检索：故人资料、家族故事）→ 组装提示词（风格配置）→ 调用 DeepSeek API（deepseek-v4-flash，流式输出）→ 输出二次过滤 → 生成"AI 标识"与对话记录 → 返回客户端。

### 8.2 技术实现

- 使用 Spring WebClient 调用 DeepSeek OpenAI 兼容端点，支持超时、重试与连接池。
- SSE 流式输出：服务端通过 SseEmitter / StreamingResponseBody 转发给客户端；用户取消时通过 context 停止模型调用。
- 安全过滤以 Spring Interceptor/Filter 实现，输入输出双重校验。
- 高频问题走 Redis 缓存；超时或失败降级为模板化回复。

### 8.3 延迟预算（目标 <15 秒）

| 环节 | 预算 |
| --- | --- |
| 网络与鉴权 | 0.2 秒 |
| 输入安全过滤 | 0.1 秒 |
| 记忆检索 | 0.2 秒 |
| LLM 生成（流式） | 8-12 秒 |
| 输出过滤与返回 | 0.3 秒 |

### 8.4 合规要点

- 使用 DeepSeek API，按服务条款确认用户对话数据不用于模型训练。
- 未成年人账号拒绝调用问答接口。
- 连续使用超 2 小时提醒；极端情绪触发安抚话术与求助入口。
- 所有问答记录入库，后台可检索复核；不当内容拦截 100%（人工复核兜底）。
- 上线前完成安全评估与算法备案准备（与开发并行）。

## 九、安全与合规架构

- 传输与存储：全链路 TLS 1.2+；对象存储服务端加密；敏感字段数据库加密；密码 BCryptPasswordEncoder。
- 认证与权限：Spring Security + JWT + 刷新令牌；后台 TOTP；用户/机构/后台三套权限模型。
- 机构隔离：partner_staff 只能访问本机构数据；隐私素材内容默认不可见。
- 未成年人保护：实名年龄核验；14 岁以下需监护人同意；未成年人账号不开放故事问答。
- 删除合规：删除工单 72 小时 SLA、双人复核；级联清理对象存储、数据库与备份。
- 审计：查询、导出、删除、审核、结算等敏感操作全部写 audit_logs。
- 深度合成预留：后续声音/影像能力上线前补齐授权记录、AI 标识与用途限制。

## 十、部署与运维

### 10.1 环境规划

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| dev | 开发联调 | 脱敏数据 |
| staging | 验收与试点预演 | 脱敏数据 + 少量真实试点数据 |
| prod | 试点/公测 | 真实数据，备份完整 |

### 10.2 构建与 CI/CD

- Maven 构建（mvn verify），springdoc-openapi 生成 API 文档。
- 提交 → 静态检查与单元测试 → 构建 Docker 镜像（Eclipse Temurin JRE 基础镜像）→ 部署 staging → 人工验收 → 灰度发布 → 生产。
- 功能开关支持远程启停（故事问答、纪念册模板等）。

### 10.3 监控与告警

- 指标：接口成功率/延迟、故事问答延迟、队列积压、存储用量、DeepSeek API 成本、JVM 内存。
- 日志：业务日志、审计日志、AI 调用日志。
- 告警：错误率、延迟、删除工单 SLA 超期、结算异常。

### 10.4 备份与恢复

- PostgreSQL 每日全量 + 实时 WAL；对象存储冗余备份；每月恢复演练。

### 10.5 成本控制

- MVP 以 2-3 台 4GB 规格 ECS/自托管主机 + 独立数据库起步（JVM 预留 512MB-1GB/实例）；静态资源走 CDN；问答按需调用并缓存；素材分级存储（热/冷）。

### 10.6 自行部署说明

- 云厂商、机房与域名由用户自行决定；本架构保持可移植：Docker Compose 编排、S3 兼容存储抽象、推送与短信配置化。
- 正式部署手册（含环境变量、备份、扩容、HTTPS 证书）在 MVP 开发期（W8 前后）输出。

## 十一、测试策略

- 单元/集成测试：JUnit 5 + Spring Boot Test + Testcontainers（PostgreSQL/Redis）。
- E2E：三端关键流程（建档、授权、问答、机构下单、后台工单）。
- 性能：问答 <15 秒、纪念册 <30 秒、并发上传。
- 安全：越权（用户/机构/后台）、删除级联、不当内容拦截、结算对账。
- 后台 SLA：删除请求 72 小时流程演练。
- 真机兼容：iOS 14+ / Android 9+ 主流机型。
