# 忆联（MemoryLink）产品需求说明书

版本：V1.7（家族关系方向 · 平权叙事版）

项目代号：MemoryLink

修订日期：2026年9月3日

关联文档：《忆联（MemoryLink）方向调整说明 V1.1》《忆联（MemoryLink）市场可行性报告 V1.4》《忆联（MemoryLink）技术架构设计书 V1.4》

## 一、文档概览

### 1.1 修订说明（V1.5 → V1.6）

- 业务框架从"纪念故人"升级为"家族记忆与亲情连接"：覆盖所有家族关系，而不只是生者与逝者的连接。
- 人物档案双态：在世成员与故人均可建档；在世成员功能（成员主页、共同回忆、口述历史）纳入 MVP。
- 故事问答面向所有人开放，启用条件分两类：在世本人主动开启；故人知情同意。
- 两项安全边界已确认：AI 问答不可由他人代开；在世未成年人不开放 AI 问答。

### 1.2 修订说明（V1.6 → V1.7）

- 叙事统一为"平权家族成员"视角：不再按长辈/晚辈/中坚分层描述角色，任何家族成员都可以讲述、整理、倾听。
- 辈分与年龄仅出现在两处：① 关系声明（邀请码认领时选择的亲属关系）；② 未成年人合规规则。
- 口述历史默认"仅本人可见"；讲述者离世后 AI 讲述默认关闭，如需继续须走故人知情同意流程。

## 二、产品愿景与使命

"让每一段家族记忆都被记录、被讲述、被传承。"

忆联是一个家族记忆与亲情连接平台：每一位家人的故事都值得被保存，家族成员围绕共同记忆彼此连接——无论亲人是否在身边。

使用场景举例：

- 妈妈录下她年轻时的一段故事，全家可回看、可整理成文字；
- 春节聚会后，家族成员共同上传照片，自动汇成"2026 春节"共同回忆；
- 清明/忌日，家族收到故人纪念提醒，共同回忆故人故事；
- 已开启 AI 讲述的家族成员，其故事可被授权家人以文字问答方式倾听（AI 标识）。

设计原则：

- 家族为本：家族树覆盖所有成员，记忆属于家族共有资产。
- 本人同意优先：在世成员的讲述与 AI 问答必须本人开启，他人不可代办。
- 克制表达：AI 问答仅基于授权内容，不编造、不冒充、不处理现实事务。
- 合规优先：功能上线前过"同意、可关闭、可删除、AI 标识"四关。

## 三、目标用户

### 3.1 C 端用户（家族成员）

本产品面向每一位家族成员，按"职能视角"而非辈分划分：

| 职能视角 | 场景 | 需求 |
| --- | --- | --- |
| 讲述者（本人） | 任何家族成员录制/上传自己的讲述 | 简单录制与保存；本人决定可见范围与 AI 讲述开关 |
| 获授权成员 | 被讲述者开放可见/授权 | 收听、阅读整理、对授权内容提问（AI 问答） |
| 共同整理者 | 获授权的家族成员 | 为口述补标题、整理文字、标注时间/主题 |
| 家族管理员 | 家族创建者/共建者 | 邀请成员、维护人物与素材、管理授权与关闭 |

说明：辈分仅用于关系声明（如邀请码认领选择"子女/配偶/兄弟姐妹"）与未成年人合规；叙事与功能不区分长幼。

### 3.2 B 端合作方

| 角色 | 描述 | 需求 |
| --- | --- | --- |
| 殡仪馆/公墓 | 告别与祭扫服务机构 | 差异化纪念服务、可复制合规工具 |
| 家族服务机构 | 家谱/口述史/影像服务商 | 家族档案与口述采集合作 |

## 四、功能范围（MVP V1.6）

### 4.1 优先级定义

P0 MVP 必须；P1 试点灰度；P2 后续迭代（需伦理、合规、技术评估通过）；P3 远期。

### 4.2 功能清单

| 模块 | 功能说明 | 优先级 |
| --- | --- | --- |
| 用户系统 | 注册/登录、实名与年龄核验、个人信息 | P0 |
| 家族与成员 | 家族树（在世/故人标记）、成员角色、邀请码加入 | P0 |
| 人物档案 | 每位成员/故人的档案：基本信息、关系、照片/录音/口述 | P0 |
| 成员主页 | 在世成员个人主页：自述、口述历史、个人素材（本人管理） | P0 |
| 共同回忆 | 家族共享相册/时间线/事件，多人共建 | P0 |
| 口述历史 | 录音/视频 + 文本整理；本人上传与授权 | P0 |
| 记忆馆 | 素材墙、纪念册、档案详情与编辑 | P0 |
| 授权管理 | 在世本人开启 AI 讲述；故人知情同意；关闭开关 | P0 |
| 节日关怀 | 在世生日 + 故人生日/忌日/清明提醒，每日 ≤1 条推送 | P0 |
| 故事问答 | 面向所有人物（按启用条件），文字问答，AI 标识与防沉迷 | P1 |
| 设置中心 | 隐私、数据导出/删除、推送与 AI 开关 | P0 |
| B 端合作后台 | 机构仪表盘/员工/订单/结算/扫码物料 | P1 |
| 后台管理 | 平台看板/审核/删除工单/机构管理/审计 | P1 |
| 商业化付费 | 订阅、机构分成 | P1 |

### 4.3 MVP 明确不包含

- 声音克隆、影像复活、AI 语音朗读（后续迭代，需伦理与备案）
- 实时语音对话、多模态表情互动
- 家族知识图谱深度挖掘
- 面向在世成员的"他人代开 AI 问答"
- 在世未成年人的 AI 问答

## 五、核心页面与流程

### 5.1 主要页面

| 页面 | 说明 |
| --- | --- |
| 首页 | 我的家人、共同回忆、纪念场景入口 |
| 成员主页 | 家族成员（含自己）的个人档案与口述 |
| 人物档案详情 | 双态：在世（本人讲述/授权）/ 故人（知情同意） |
| 共同回忆 | 共享相册/时间线/事件 |
| 聊天界面 | 故事问答（AI 标识） |
| 家族树 | 全家族关系，含在世/故人标记 |
| 设置中心 | 隐私、权限、AI 开关、删除 |

### 5.2 关键流程

1. 建家族与邀请：创建家族 → 邀请码/手机号邀请成员 → 加入者声明关系。
2. 人物建档：选择在世/故人 → 填写信息 → 上传素材/口述 → 相应授权。
3. 在世讲述：本人实名 → 录制"我的讲述" → 本人开启 AI 问答（不可代办）。
4. 故人授权：近亲属提交知情同意（生前预授权或两名近亲共同确认）。
5. 故事问答：仅对已开启/已授权人物开放，带 AI 标识与防沉迷。
6. 关闭与删除：任何可关闭对象支持随时关闭；删除请求 72h SLA。

## 六、功能需求明细

### 6.1 用户系统（P0）

- 注册/登录（手机号+验证码/微信）、实名年龄核验。
- 未成年人规则：不向未成年人提供虚拟亲属/伴侣服务；在世未成年人不开放 AI 问答；14 岁以下使用需监护人同意。

验收：注册 60 秒；实名年龄字段完整。

### 6.2 家族与成员（P0）

- 家族树支持多代、姻亲；人物标记在世/故人。
- 邀请码（16 位、哈希存储、单次、可撤销）与手机号邀请；成员角色 OWNER/EDITOR/VIEWER。
- 成员关系与证据状态（SELF_DECLARED/待核验）留痕。

### 6.3 人物档案（P0）

- 双态字段：is_deceased（在世/故人）、与当前用户关系、口述列表。
- 故人保留知情同意链路；在世由本人管理。

### 6.4 成员主页与口述历史（P0）

- 本人可维护自我介绍、头像、照片/录音；可录制口述（≥1 段）与文字整理。
- 本人决定口述对哪些成员可见；本人开启"AI 讲述"后故事问答可用。

口述历史 user story（平权家族成员叙事）：

1. 作为任何一位家族成员，我希望用简单的方式录下我的口述（可暂停续录、分章节），以便故事被家族留存，无论今天还是多年后回看。
2. 作为讲述者本人，我希望自己决定哪些家族成员能看、是否开放 AI 讲述，以便我讲的故事只流向我愿意分享的人。
3. 作为获授权的家族成员，我希望为讲述补充标题、整理成文字、标注时间与主题，以便故事更好检索、更易被后人理解。
4. 作为家族成员，我希望在授权范围内收听与阅读家族成员的讲述，以便了解这个家的来处。
5. 作为讲述者本人，我希望随时删除我的口述并同步清除 AI 引用；讲述者离世后由家族按其生前授权与故人知情同意规则处理。

默认规则（已确认）：

- 口述历史默认"仅本人可见"，由本人逐步开放；
- 讲述者离世后 AI 讲述默认关闭；如需继续，须走故人知情同意流程。

### 6.5 共同回忆（P0）

- 事件化相册（节日/聚会/旅行），成员可上传、评论、时间线展示。

### 6.6 记忆馆与纪念册（P0）

- 素材墙（照片/录音/视频），支持预览、删除；纪念册模板化。

### 6.7 节日关怀（P0）

- 在世生日 + 故人生日/忌日/清明；每日 ≤1 条、夜间静音、可关闭。

### 6.8 故事问答（P1）

- 启用条件：在世本人实名并主动开启；故人有 VALID 知情同意；未启用返回引导文案。
- AI 标识、2 小时提醒、极端情绪支持、未成年人禁止、不处理现实事务。
- 仅基于授权档案与口述内容回答，不编造。

### 6.9 授权管理（P0）

- 在世："本人开启 AI 讲述"（人脸/实名二次确认，留痕，可关闭）。
- 故人：PRE_AUTHORIZED / TWO_RELATIVES，记录可审计。
- 所有授权记录可导出；关闭 72h 内生效。

## 七、B2B2C 渠道产品设计

### 7.1 目标

机构获客 → 家属建档 → 服务付费 → 分成结算，闭环可复制、可结算、可审计。

### 7.2 角色与权限

机构管理员/一线员工/机构财务/平台侧；机构不可查看客户隐私内容。

### 7.3 生命周期与功能

签约入驻 → 配置上线 → 引导建档 → 服务交付 → 月度对账 → 续约/退出；含机构仪表盘、员工管理、扫码物料、订单、结算中心。

### 7.4 渠道 KPI

机构激活率 ≥80%、扫码→建档 ≥60%、月均订单 ≥10 单、续约率 ≥70%、渠道投诉 <1%。

## 八、后台管理（平台运营端）

用户与家族管理、内容与安全审核、伦理与合规工单（删除 72h SLA）、机构管理、结算审核、风控审计、运营配置、数据看板；删除双人复核、审计 ≥6 个月。

## 九、非功能性需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏 <2s；问答 <15s；素材上传 ≤100MB |
| 安全 | TLS、bcrypt、JWT、双因素（后台）、审计日志 |
| 隐私 | 数据导出、永久删除（含备份）、本人同意优先 |
| 合规 | 备案准备、AI 标识、防沉迷、未成年人规则 |
| 可用性 | 中文、老年模式、3 步可达 |
| 兼容 | iOS 14+/Android 9+ |

## 十、AI 能力说明

### 10.1 MVP AI 能力

仅文字故事问答。启用规则：

- 在世人物：本人主动开启 + 实名（不可代办）；未成年人不开放；
- 故人：VALID 知情同意。

### 10.2 技术路线

DeepSeek（deepseek-v4-flash）OpenAI 兼容端点；结构化检索授权档案/口述；SSE 流式；输入输出安全过滤。

### 10.3 后续迭代

声音克隆、影像生成、AI 语音朗读需伦理评审 + 备案 + 技术评估后启动。

## 十一、数据结构（演进方向）

- loved_ones → 人物档案（V3：新增 is_deceased 默认 true、person_status、ai_persona_enabled、开启人/时间）；
- 口述历史：media_files 复用或新增 oral_histories（音频/视频 + 文本）；
- invite_keys、family_members.evidence_status（V2 已建）；
- 家族关系边：family_relationships（后续迭代）。

数据规则：授权记录与审计日志不可被普通用户删除；永久删除级联。

## 十二、API 接口清单（示例）

认证/档案/家族/素材/问答/授权/邀请/机构/后台管理主要接口沿用 V1.5，新增：

- POST /api/v1/persons/{id}/ai-consent（在世本人开启 AI 讲述）
- POST /api/v1/persons/{id}/oral-histories（口述上传）
- GET /api/v1/families/{id}/memories（共同回忆）

## 十三、伦理与法律合规

| 对象/要求 | 落地 |
| --- | --- |
| 在世本人 | 本人同意、敏感信息单独授权、可删除 |
| 故人 | 知情同意、永久关闭 |
| 未成年人 | 不开放 AI 问答、14 岁以下需监护人 |
| AI | 标识、防沉迷、备案准备 |
| 数据 | 家族共有、可导出、可删除、审计 |

## 十四、商业试点与运营

- 试点：1-2 家机构 + 50-100 个家庭；
- 指标：建档完成率 ≥60%、7/30 日留存 ≥30%/≥15%、付费转化 ≥5%、故事问答满意度 ≥4/5、删除 72h 100%；
- 在世成员功能随试点一并验证（口述历史、共同回忆的使用率）。

## 十五、发布计划

合规与原型 1-4 周；MVP 开发 5-12（含 V3 数据迁移）；机构试点 13-16；迭代 17-18；内测 19-20；公测 21-22。
