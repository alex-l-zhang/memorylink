# 忆联 · 场景素材生成描述 V1.1

用途：交给 AI 绘图工具，批量生成"身后空间与居所"的成套场景照片。

配套阅读：`prototype/素材来源与授权.md`（为什么不能再从网上抓图）、`忆联_身后空间与居所设计_V1.0.md` 4.2–4.4、`prototype/tools/scene_grade.py`（客观打分脚本）。

## V1.1 改了什么

V1.0 是依据原型锚点需求写出来的初稿，没经过出图验证。2026-09-12 拿到首轮生成结果（`docs/高山湖小屋写实图生成.png`，豆包生成，"湖畔书舍 · 黄昏"），与当前首页图逐项比对后确认：**V1.0 的提示词本身漏掉了几条决定观感的要求，其中一条还是我们自己写错的。** V1.1 据此修订。

| 首轮出图暴露的问题 | 实测证据 | V1.1 的修订 |
| --- | --- | --- |
| 全画面被暖光铺满，没有冷色环境 | 全图 R-B 三条横向带均为正：+0.069 / +0.126 / +0.156 | 通用前缀与三段光照都加了"冷色环境光 + 暖光只落在受光面" |

## 一、先看这五条硬性要求，做不到的图直接废

1. **空镜，且没有平台水印**。画面里不能有人、宠物、车、船（有人的）、门牌号、招牌、文字、logo、平台水印。人物涉及肖像权，文字和品牌涉及商标，门牌涉及隐私——这几样在生成阶段就要排除，不要指望后期修。水印同理：不少国内工具默认会在角上烧一个"XX生成"，能在出图设置里关掉就关掉，关不掉就换工具——靠裁角去水印是有代价的，会把构图和锚点一起裁掉。
2. **窗户要"可见但不预先点亮"**。这是内容驱动机制的前提：家人的多少决定亮几扇窗。如果底图里窗已经全亮了，客户端再怎么加灯都看不出来。三个时段都要求窗户是可辨识的暗面。
3. **构图要给锚点留位置**。房屋正面（含每扇前窗和正面那扇门）必须清晰可见、大致均匀分布，且房子占画面宽度的 40%–55%、偏左或居中；画面下缘留出干净的地面或水面。我们后面要把窗灯、门口灯、长明灯锚在真实的窗户和门上——第一版原型锚点漂到树上，就是因为底图的窗和门不够清晰。注意"均匀分布"说的是窗和门各自看得清，**不是让模型给你排一排等大等距的窗**：那是旅馆立面，不是家，而且会让"谁家亮着灯"变成一条进度条。
4. **一套场景三个时段必须是"同一栋房子"**。做法见第七节：固定随机种子，或者用清晨那张当参考图做图生图。
5. **影调要有层次、冷暖要有对撞**。这条听起来虚，但可以量化，阈值和打分脚本见第八节。一句话版本：**整张图应该是一个冷色的环境，加一处暖光的落点**——冷色的天光与背光面，对比暖色的受光面与室内灯。如果整幅图被同一盏暖光均匀铺满，就会像首轮那张一样"平"。

规格：横构图 16:9，出图不低于 1920×1080（我会裁成产品要的 1600×900）。

## 七、不同工具的实操

**Midjourney**：`--ar 16:9 --style raw --v 6.1`，再加一个固定 `--seed 12345`。先用清晨段出一张满意的，**记下 seed**，然后只替换光照段重跑，就能得到同一栋房子的黄昏与夜晚。

**Flux / Stable Diffusion**：1920×1080，steps 30–40，guidance 4–6，seed 固定。若换时段后房子变形，改用图生图：以清晨那张为参考图，denoise 0.4–0.55，光照段换成黄昏或夜晚。

**国内工具（即梦 / 通义万相 / 文心一格 / 豆包等）**：用中文段，尺寸选 16:9 / 1920×1080，风格选"写实 / 摄影"。多数不暴露 seed，就用"参考图 / 图生图"：拿清晨那张当参考，强度调到中低，再换光照描述。**出图前先在设置里把水印 / 角标关掉**，出完图放大看右下角有没有残留——首轮那张右下角就烧着"豆包AI生成"。

**通用建议**：每个场景先生成 8–12 张挑 1 张。挑图的标准不是"好看"，而是第二节那条——**窗户和门清不清楚、房子是不是占了该占的位置**，因为后面要往上面锚灯。剩下的"好不好看"里，能客观量化的部分交给下面的打分脚本。

## 八、挑图验收清单

- [ ] 画面里没有人、动物、车、文字、招牌、门牌号、logo、平台水印
- [ ] 正面每一扇窗都清晰可辨，室内未点灯（夜晚版允许门边一盏小壁灯）
- [ ] 正面有一扇看得清的门
- [ ] 房子占画面宽度 40%–55%，偏左或居中，下缘有干净的地面或水面；窗户大小与位置有变化，不是一排等大等距的旅馆立面
- [ ] 横构图 16:9，长边 ≥1920
- [ ] 同一场景的三个时段是同一栋房子（屋顶形状、窗的数量与位置、烟囱、门的样式一致）
- [ ] 没有鱼眼畸变、地平线不歪、没有 HDR 光晕和过饱和
- [ ] 跑一遍客观打分，没有"不合格"项（命令见下）

### 客观打分：`prototype/tools/scene_grade.py`

清单里前三条靠肉眼看，后面的影调问题靠看很难说清"差多少"。这个脚本把能量化的部分量出来，**基准是当前首页图**（`prototype/public/scenes/lake-study.jpg`，1600×900）：

```bash
python3 prototype/tools/scene_grade.py 候选图.jpg 候选图2.png
```

它会给每张图打分并逐条给"通过 / 注意 / 不合格"。首轮那张图（B）与首页图（A）的实测结果：

| 指标 | A 当前首页图 | B 首轮生成图 | 阈值 | B 的判定 |
| --- | --- | --- | --- | --- |
| 画面比例 / 分辨率 | 16:9，1600×900 | 16:9，2848×1600 | 16:9，长边 ≥1920 | 通过 |
| 局部细节（质感层次） | 16.3 | **11.5** | ≥13.0 | 注意（低约 30%） |
| 死黑像素占比 | 0.03% | **1.83%** | ≤0.5% | 不合格 |
| 亮度 99 分位 | 231 | 246 | ≤240 | 注意（高光接近溢出） |
| 天空区饱和度 | 0.137 | **0.077** | ≥0.12 | 不合格（天空发白） |
| 冷暖关系（R-B：上 / 中 / 下） | −0.033 / −0.083 / −0.047 | **+0.069 / +0.126 / +0.156** | 应有冷底 + 暖点 | 注意（全画面偏暖） |
| 水面镜面度 | 0.27 | **0.71** | ≤0.55 | 注意（接近镜面） |

**结论：B 不是"不好看"这种主观判断，它在四个方向上有可复现的量化差距——质感差 30%、暗部压死、天空发白、全画面被单一暖光铺满。** 而首轮这张本来就是照 V1.0 的提示词出的，V1.0 里恰好缺了对应约束（还写错了"平静如镜"），所以这一轮的差距**主要来自提示词，而不是工具**——换回同一批提示词再出一轮，才能判断工具本身够不够用。

## 十、还没解决的

- **生成内容的商用与标识**：所选工具的商用条款、以及生成合成内容的标识要求，需要在上线前核实（见 `prototype/素材来源与授权.md` 第四节）。
- **V1.1 只验证过一轮、一个场景、一个工具**：所有阈值来自"豆包出的湖畔书舍 · 黄昏 vs 首页图"这一组对比。修订到底补没补上差距，得再出一轮同场景的图才知道；跑完请回来更新第八节那张实测表。
- **"窗户保持暗面"这条还只被验证了一半**：首轮那张确实做到了（窗是暗的），但代价是画面因此更平；而当前首页图反倒是一张窗户已经亮着的图。这两件事在拉扯——真正要的目标不是"像首页图那样亮"，而是"窗是暗的，画面里另有暖光点"（檐下灯、远处另一栋房子的灯）。如果换几轮都出不来，就得回产品侧讨论：底图窗暗、客户端叠加的暖光范围是不是要放大一档。
- **三时段一致性还没测**：同一栋房子的清晨 / 黄昏 / 夜晚能不能靠 seed 或图生图锁住，一次都还没跑过。
