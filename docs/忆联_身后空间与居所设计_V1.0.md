# 忆联（MemoryLink）身后空间与居所设计

版本：V1.0（初稿）

制定日期：2026年9月12日

关联文档：《忆联_产品需求说明书 V1.9》《忆联_试点项目计划 V1.5》《忆联_技术架构设计书 V1.7》《忆联_市场可行性报告 V1.5》

修订说明：本文档提出并细化"身后空间（百年后的房子）"与"居所（虚拟位置与房型）"两项产品设计，作为家族网络之外的第二条价值路径。文中所有结论均标注来源类型：【事实】（可查证）、【推断】（有推理链）、【待验证】（需实测或查证）。

本文档**不代表开发启动**，用于记录设计决策与待决策事项；正式进入开发前需先完成第十一章的验证与第十二章的待决策项。

## 一、背景与动机

### 1.1 为什么需要这条路径

【事实】截至 2026-09-12，系统内 51 位用户对应 52 个家族，其中 28 个家族只有 1 名成员，家族平均成员数 1.63 人。

【事实】50 条家族关系中，双向已确认（ACTIVE/ACTIVE）29 条，占 58%；双方均待确认 11 条；出现拒绝的 4 条。

【推断】以上两组数据说明"先建网络、再由网络产生价值"的路径存在结构性困难：网络需要多人协同才能成形，而用户缺少单人即可成立的理由。因此需要一条**单人即可完成、单人即有价值**的入口。

### 1.2 本方案的两个组成部分

1. **身后空间（百年后的房子）**：用户在世时为自己准备、在其无法操作后启动的纪念空间。
2. **居所（位置与房型）**：该空间在现实世界中通常不可能存在的位置与形态（海边、森林、湖畔、高山、闹市、乡村；大宅、小木屋、书舍等），作为情感载体与身份表达。

### 1.3 为什么二者应当一起设计

【推断】写实的"纪念空间"天然带有殡葬观感，对普通家庭用户有劝退效应；而"梦想中的居所"传递的是"给自己一个地方"。居所把身后空间的情感基调从"安排身后事"改写为"住进一个地方"，这是本方案成立的前提之一。

## 二、设计目标

- 目标 1：单人即可完成并产生价值，不依赖家族网络成形。
- 目标 2：同意链最干净——由本人在世时自主安排，不依赖身后由他人代授权。
- 目标 3：现在就有用，而不是无法操作之后才有用。
- 目标 4：对家人是减负（不必猜测、不必争执），不是新增负担。
- 目标 5：与主产品（家族记忆）形成互相喂养的关系。

## 三、核心机制：三代共写

### 3.1 机制说明

入口不是"为自己建一座身后的房子"，而是"家里有人在问你问题"。祖辈回答、孙辈提问并记录，内容自动沉淀进其居所；当事人无法操作后，这些内容自然成为纪念空间。

角色分工：

- 祖辈：被问、讲述（门槛低，且被需要）；
- 中年子女：组织者，负责发起提问与记录；
- 年轻人：提问者与整理者。

### 3.2 为什么以"提问"为入口

【推断】以"准备身后事"为入口，用户行为表现为拖延，因为它不急；以"有人问我"为入口，行为是即时的，因为动力来自人际而非产品。

【事实】系统已具备文字故事问答能力（DeepSeek，问答记录落库 conversations 表），可作为该机制的内容引擎，无需新增 AI 能力。

### 3.3 与"不做声音克隆、影像复活"的关系

【事实】产品决策已明确 MVP 不做声音克隆与影像复活。本机制不依赖上述能力：内容载体为文字问答、音频原声与照片，均属既有能力范围。

## 四、居所设计

### 4.1 位置属于家族，房间属于个人

【推断】若允许每位成员各自选择位置，会产生"父亲选海边、女儿选森林，这户人家的房子在哪里"的冲突。因此确定：

- **位置属于家族**：一座房子一个位置，由家族成员商定，可变更；
- **房间属于个人**：个人表达落在房间内部（例如我的房间是书房、父亲房间朝南）。

### 4.2 表现形态：插画场景，不做 3D

【事实】《产品需求说明书 V1.9》第十章非功能需求对可用性的要求为"中文、老年模式、3 步可达"；目标用户包含大量 60 岁以上老人。

【推断】3D 可漫游空间与"3 步可达"存在直接冲突，且在低端设备与微信内置浏览器上性能风险较高。用户需求的核心是"一眼看见这是我的地方"，而非"能走进去"，插画场景可满足前者。

### 4.3 内容策略：成套场景，不做"位置 × 房型"组合

【推断】6 个位置 × 6 种房型 = 36 个组合，再叠加"空置 / 有人住 / 内容充实"三种状态，美术件将达上百，超出小团队可持续产出范围。**（以下为估算，非实测数据）** 成套场景方案（8 个场景 × 3 种状态 = 24 件）在工作量上约为组合方案的 1/5 至 1/9，且每个场景的位置与房型匹配度更高。

因此确定：**每个场景是一个完整成品（位置与房型绑定），不做自由组合。**

### 4.4 关键机制：居所随内容变化

【推断】静止的居所与"选择主题皮肤"没有区别，用户短期即失去新鲜感。要让居所承担回访理由，需使其随内容变化，且变化由内容驱动、美术仅提供有限状态：

| 触发 | 居所变化 |
| --- | --- |
| 放入第一张全家福 | 客厅墙上出现该照片 |
| 累计讲述达到阈值 | 书架逐渐填满 |
| 新成员加入 | 房屋增加亮灯的房间 |
| 老照片修复完成 | 墙上照片由模糊变清晰 |
| 成员离世（本人或家人） | 门口增加一棵树或一盏灯 |

【推断】该机制使"装修"从一次性行为转为持续回访理由，同时避免美术成本随内容线性增长。

### 4.5 居所内的功能区

| 功能区 | 在世时的作用 | 无法操作后的作用 |
| --- | --- | --- |
| 居所封面（名称 + 一句话） | 个人自留地 | 纪念空间封面 |
| 相册墙（本人挑选的照片） | 整理老照片 | 希望被记住的样子 |
| 讲述（口述 / 问答记录） | 家人正在问我 | 家族口述史 |
| 留给某人的话（指定收件人与开启时间） | 说出难以当面表达的话 | 到期送达 |
| 交代清单（可选） | 心里有数 | 家人不必猜测、不必争执 |
| 门与钥匙（可见性 + 执行人） | 我决定谁能进 | 由执行人启动 |

【推断】所有条目均为可选，一段 30 秒录音即可使居所成立；不设必填项，避免"空房子即家务"。

## 五、三个关键机关

### 5.1 按时赴约

预先留下的文字、声音或照片，在特定日期（生日、忌日、结婚纪念日、清明等）自动送达指定家人。

【推断】相比"AI 复活"，该机制技术风险近乎为零（仅要求准时），且情感表达更克制、更易被家人接受。

### 5.2 选择性公开

支持"到某一天再拆"的内容，可指定单一收件人。

【推断】这是本产品相对通用社交与云存储最不可替代的能力：现有工具无法表达"这句话现在不能让活人看到"。

边界要求：**接收方拥有"暂不接收"的权利**。由系统在对方不知情时推送遗属内容，可能造成心理伤害，须提供开关。

### 5.3 低门槛

最小可完成单位为"一句话、一张照片、一段 30 秒录音"。不设表单、不要求一次完成。产品必须支持"今天放一件"的渐进节奏。

## 六、与家族网络的关系

【推断】身后空间与居所是家族网络的**楔子**而非转向：用户建好自己的居所 → 放入家族照片与讲述 → 需要邀请子女来看、来听、来补充 → 家族网络自然生长。该路径的起点是单人可完成、情感强度高的动作，网络是副产品。

因此现有关系模型、可见性与权限设计继续有效，只是不再承担"冷启动"职责。

## 七、可见性与隐私边界

| 层级 | 判定 | 可见内容 |
| --- | --- | --- |
| 门廊（未登录） | 持有邀请令牌 | 邀请人姓名与"邀请你加入"；不含其他成员 |
| 家族居所 | 家族成员 | 位置场景、公共空间内容 |
| 个人房间 | 房间主人授权 | 房间内内容 |
| 指定内容 | 逐条授权 | "留给某人的话"等 |

红线：

- 不提供"输入姓名即可检索他人"的公网搜索；
- 故人（无在世授权方）的信息不匿名展示；
- 区分"可分享"与"可搜索"：用户主动分享的卡片可有内容，公网不应可索引。

## 八、与现有实现的差距

| 议题 | 现状（可查证） | 需改动 |
| --- | --- | --- |
| 房间槽位（未注册家人先有房间） | family_members.user_id 为 NOT NULL，无法表达"房间已备、人未入住" | 需扩展表结构以支持认领式入住 |
| 房屋产权 | families.creator_id 为单一 NOT NULL 字段 | 夫妻共有需多产权人模型 |
| 私有空间 | 家族 OWNER/EDITOR 可编辑与访问户内全部档案（LovedOneService 的 canManage/canAccess） | 需将"房屋管理权"与"房间隐私"分离 |
| 身后空间启动 | 无执行人机制；AccountService.delete 为物理删除，无其他成员时整户 purgeFamily | 需执行人指定 + 触发流程 + 注销规则例外 |
| 亲属关系录入 | 已支持具体称谓与双向确认 | 需按"父母/配偶/子女"基础边 + 推导方向收敛（另见关系模型议题） |
| 居所场景 | 无 | 全新 |

【事实】现存的"不做占位节点"决策（PRD V1.9 §8.1）针对的是**关系图谱中的占位节点**（两兄弟各建一个"舅舅"引发实体消歧）。本方案中的"房间"位于房屋内部、作用域限于单户，与该决策的作用域不同。**是否正式修订该决策，列为待决策事项。**

## 九、商业模式与渠道

- 免费：居所、基础内容、基本分享。
- 付费：呈现与时间（更长存储、更多"留给某人的话"、指定执行人）、实体输出（家族纪念册、老照片修复相册）。
- 渠道（B2B2C）：养老机构、殡葬服务机构、寿险可作为入口；机构侧销售"生前契约"，本产品提供其中的数字部分。

红线：不得设计为"家人续费否则内容消失"；不对"被记住"本身收费；加入家族永久免费。

## 十、设计红线（不做清单）

1. 不做 3D 可漫游空间。
2. 不做位置稀缺、涨价或可交易（虚拟地产的投机模式已有失败先例）。
3. 不做系统自动判定死亡；必须由指定执行人触发，设冷静期且可撤销。
4. 不做公开纪念页目录与公网人物检索。
5. 不做 AI 复活、声音克隆、影像生成（沿用既有决策）。
6. 不在接收方不知情时推送遗属内容。
7. 不使用"遗言""墓地""数字墓园"等表述。
8. 不以"虚拟豪宅"作为对外主卖点；主卖点仍为"留住家里人的声音和照片"。

## 十一、待验证假设与验证方案

| 假设 | 验证方式 | 验收标准 |
| --- | --- | --- |
| 存在"想留给某个人一段话"的真实需求 | 访谈 10 位 60 岁以上老人 + 10 位 35-50 岁子女，各 20 分钟 | ≥6 人能立即说出具体收件人 |
| "居所随内容变化"能形成回访动机 | 出 1 张场景图（含 3 张照片在墙、书架空置的状态），10 人评审 | 多数人能说出想放谁的照片，并对"书架满了"有画面感 |
| 年轻用户接受"居所"隐喻 | 同上评审，分层统计 25-35 岁反馈 | 待定（本轮为假设） |
| 生前契约市场规模 | 查证上市公司年报与行业报告 | 不引用未经核对的数据 |

访谈问题应针对行为而非意愿：

1. 你家有没有一张你父母年轻时的照片，是你不知道来历的？
2. 关于自己走的时候的事，你跟谁说过？
3. 如果有一个地方可以留一段话给一个具体的人，你想写给谁？
4. 你父母或你自己，有没有什么话是从没跟任何人说过的？
