# 忆联 · 身后空间与居所（设计原型 V2.0）

把《忆联_身后空间与居所设计 V1.0》里的设计机制做成可点、可看的前端原型，用于设计验证与内部讨论。

**这不是产品功能，也不是可上线的应用。** 没有后端、没有账号、没有真实存储，数据只活在页面内存里，刷新即回到初始状态。

## V2 改了什么

V1 的场景是矢量拼装的示意图。2026-09-12 评审结论是"画面太简陋，要真实感"，因此 V2 把表现形态换成：

**一张真实照片底图 + 少量叠加层**。照片负责"真实"，叠加层负责"随内容变化"：

| 叠加层 | 怎么变 | 机制来源 |
| --- | --- | --- |
| 窗里的灯 | 家人越多，亮着的窗越多（上限为场景锚点数） | 4.4 新成员加入 → 亮灯的房间 |
| 相册墙 | 每放一张照片，墙上多一个相框，最多 9 个 | 4.4 放入第一张全家福 |
| 书架 | 每段讲述填 3 本书，最多 27 本 | 4.4 讲述达到阈值 |
| "之后"的门口灯 | 切到"之后"亮起 | 4.4 成员离世 → 门口一盏灯 |
| 长明灯 | 每位故人一盏 | 同上 |

同一张照片通过三种时段调色（清晨 / 黄昏 / 夜晚）+ 缓慢推镜 + 雾气 + 胶片颗粒 + 暗角呈现三种样子，**不需要为每个时段各拍一张照片**——这是能把美术成本压在小团队可承受范围内的关键。

## 建议的演示顺序

1. **居所页**：点右上角"屋里"，看外景与屋里两种视角。屋外是真实照片，屋里是真实室内照片做氛围、前景是自家的相册墙与书架。
2. **放一件**（底部）：依次点"一张照片""一段讲述""一句留给某人的话"，看相框、书架、信箱同时变化——这是"居所随内容变化"的核心机制。
3. **时间**：在"清晨 / 黄昏 / 夜晚"之间切换，看同一座房子的光。
4. **换个地方**：换一个居所。每个地方是"位置 + 房型"的一个完整成品，不做自由拼装。
5. **切"之后"**：右上角"现在 / 之后"开关，看同一间屋子的另一副样子——门口亮灯、长明灯亮起、信件进入待送。
6. **留给某人的话**：看"到那天才打开"的信，以及收信人的"暂不接收"开关。
7. **钥匙**：点"推进一步"，走完 指定开门人 → 申请 → 7 天冷静期 → 开启 的全过程。
8. **一起写**：念念提问 → 爷爷回答 → 这段讲述自动进入书房。
9. **边界**：四层可见性与 8 条设计红线。
10. **门口看一眼**：未登录访客看到的门廊，只暴露门牌级信息。

## 场景锚点怎么维护

窗灯、门口灯、长明灯的位置都是**照片的百分比坐标**，写在 `src/data.ts` 的 `SCENES` 里。底图统一裁成 1600×900（16:9），所以"按比例铺满画面"等于"不裁切"，百分比可以直接对着照片量。

改完锚点后跑一次校准脚本，看方块是否压在真正的窗户上：

```bash
python3 tools/scene_check.py /tmp/scene-check    # 黄框=窗灯，红框=门口灯，绿点=长明灯
```

换照片时先用 `tools/prepare_scenes.py` 裁成 16:9：

```bash
python3 tools/prepare_scenes.py 原图.jpg public/scenes/xxx.jpg
```

**注意**：照片和窗灯必须放在同一个 `scene-world` 图层里一起做推镜，否则照片动了、灯没动，锚点会漂。

## 验证

```bash
npm run build                                      # 类型 + 构建
NODE_PATH=<装了 playwright 的目录> node tools/visual_smoke.cjs http://127.0.0.1:5190/
```

视觉冒烟测试用真实 Chromium 检查：底图确实是照片、亮灯数正确、相框与书架随内容增长、"之后"有灯、换地方换的是照片，并断言**没有加载失败的图片、没有控制台错误**。jsdom 只能验文字和点击，验不了这些。

## 素材来源（重要）

【事实】`public/scenes/` 与 `public/album/` 里的照片是**演示用素材**（Unsplash 精选，经 picsum.photos 取用），只用于设计评审，**不是可上线素材**。正式产品需要：

1. 自有拍摄或已授权的成套场景照片（按设计规划为 8 个场景）；
2. 每个场景补三张时段照片或确认单张 + 调色方案；
3. 相册墙照片同样需要用户自己上传，原型里的只是占位。

## 原型没有做的事

- 没有后端、没有真实数据落库、没有登录与权限校验
- 不做 3D 可漫游空间（这是设计决策，不是没来得及做）
- 场景实现了 6 个，设计规划为 8 个成品场景
- 场景照片与相册照片都是演示素材，不是自有素材
- 所有人物与事件均为虚构演示数据
